我解决的不是“再做一个 CRM”

外贸销售真正缺的是：每天不知道先看谁、为什么值得跟、下一步怎么写，以及哪些动作必须由人确认。

原问题

线索多，但研究和判断很慢

公开资料分散在官网、目录、内容互动和展会名片里。销售需要反复查资料、判断需求、整理产品参数，容易把时间花在低价值账户上。

作品方案

系统先完成“准备工作”，人做关键决策

系统按证据记录、公司去重、需求信号、产品匹配和合规门槛进行处理，给销售一条白话结论：为什么值得跟、缺什么资料、建议下一步是什么。

一条线索如何变成一次跟进

下面是作品里最重要的业务闭环。每一步都能在交互 Demo 中看到对应页面或状态。

1
发现线索官方公开页面、企业自媒体互动、展会名片等合规来源。
2
核验公司去重域名、确认企业类型、记录来源和证据日期。
3
匹配产品结合 WorkTex 的 6535 斜纹/府绸资料，给出适配理由。
4
准备联系生成报价准备单、英文草稿和回复分类，但不自动发送。
5
人工跟进销售确认后写入跟进记录，老板看到来源和转化结果。

知识库 + 分层 Skill：隐藏在后台的自动化方法

前端不要求销售理解技术名词。知识库和 Skill 在后台协同，把“资料检索、判断、生成、审批”拆成可维护的小动作。

一个总控，三组子 Skill，各自只做一件事

销售情报总控安排顺序、检查权限、决定是否交给人工
线索处理 Skill去重 / 证据 / 评分 / 风险拦截
商务准备 Skill产品匹配 / 报价字段 / 英文草稿
跟进与审批 Skill回复分类 / CRM动作 / 人工确认

知识库维护的是产品、样品、测试、交期和地区规则；Skill 维护的是处理步骤和权限。这样既能持续升级，也能在出错时定位是哪一步出了问题。

老板能看到的增长证据

不是只展示“有多少线索”，而是展示系统如何让有限的销售时间流向更值得跟进的账户。

8公开目标账户
均带来源链接与人工核验标记，不冒充真实采购意向。
5步自动处理链路
每条线索都能查看完成、等待人工或补资料的状态。
2个前端工作台
老板看增长和风险，员工看今日任务和跟进动作。

我的贡献

从行业假设到可演示系统

  • 聚焦一家只卖 1–2 款面料的虚拟外贸公司。
  • 建立产品知识库、分层 Skill、评分规则和人工审批边界。
  • 完成老板/员工双工作台、日期筛选、来源分析和自动化运行记录。
  • 用 Python + SQLite 保留可替换真实 API/CRM 的数据管线。
下一步

如果进入真实项目，我会这样落地

  • 先接入公司自有内容账号和官网表单，保留原始互动证据。
  • 再接入授权的目录、展会或 CRM 数据，不做无授权抓取。
  • 以“人工确认率、研究耗时、首次跟进用时、有效回复率”做小范围试点。
  • 通过真实反馈迭代知识库和子 Skill，而不是直接追求全自动发送。
